# SCH-110 Monotonic Scheduler Software Evidence

**Date:** 2026-08-23  
**Milestone:** SCH-110 software evidence ready; physical qualification not run  
**Scope:** Tier-1 selection, visit extension, Unknown visits, revisit timing, and RF exposure gaps

## Result

**PASS — deterministic software scheduling and fault invariants.**

The scheduler uses monotonic time and deterministic least-laxity ordering for Tier 1. The documented first-cycle phase is represented by schedule-only anchors. A phase anchor is not an RF observation, so each target needs two real valid completions before the application publishes one completion-to-completion revisit measurement.

Unknown visits retain their fault cause and never advance the valid-completion clock. A visit with incomplete but accepted RF frames remains Unknown while preserving its real exposure interval. A zero-frame visit does not invent an exposure boundary. The next real exposure therefore closes the full actual unobserved gap.

Extension beyond the nominal visit budget remains bounded by the target maximum and is admitted only when the active objective and Tier-1 look-ahead remain feasible. The default fast profile consumes 100% nominal tuner capacity, so optional work is not admitted.

## Migration and rollback

No persisted configuration, catalog, baseline, incident, or evidence schema changes are required. The new phase-anchor option is internal scheduler state created at process start. Rollback changes scheduling code only and must not delete or rewrite evidence produced by the newer package.

## Qualification boundary

This is software evidence, not RSPdx timing qualification. It does not establish real command-to-confirm, settle, third-frame, visit, revisit, USB, SDRconnect, host-load, or RF-chain behavior. Gates V2 and V7 must still preserve and report the real fault matrix and at least 24 hours of installed receiver timing. The 2/6-second values remain measured objectives, not guarantees.
